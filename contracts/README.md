# STS2 Contracts

This directory is the single source of truth for data exchanged between the
game Bridge, MCP server, RL clients, and headless simulator.

## Compatibility rules

- Wire API versions use semantic versions. The current v2 API is `2.0.0`.
- Every session advertises only API versions and capabilities that are actually
  enabled for that process.
- `player-control`, `training`, and `legacy-privileged` use distinct opaque
  bearer tokens. Training and legacy-v1 are disabled unless explicitly enabled.
- The deprecated top-level session `token` exists only when legacy-v1 is
  enabled; v2 clients select a token from `capability_tokens`.
- `GET /health` is public and deliberately minimal. `GET /v2/health`
  requires any currently published scoped token.
- Player mutations require a caller-generated `request_id`, session identity,
  the `player-control` capability, an expected state revision, and an absolute
  deadline no more than 120 seconds in the future. `wait_after_ms` is bounded
  to 0-5000 milliseconds.
- `GET /v2/events` emits only bounded frontier-revision notifications. Clients
  fetch `/v2/state` after a newer revision instead of receiving full state in
  every server-sent event.
- Environment reset requires `expected_state_version`; environment step
  requires `episode_id`, `expected_step_index`, and exactly one of
  `action_index` or canonical `action_handle`. Contract-v2 does not accept the
  legacy `action_id` alias.
- V2 training state and committed reset/step results expose each legal
  action's sole wire identity as `action_handle`; `action_id` remains confined
  to legacy-v1 and internal adapters.
- A repeated `request_id` within the advertised retention window returns the
  original result and never executes the mutation twice. Clients generate a
  fresh UUID for every new intent and never reuse an expired identity; a status
  lookup after retention may return `command_not_found`.
- Command-result `ok` is true only for `accepted`, `executing`, and
  `committed`; each status has a schema-enforced set of result/error fields.
- The Bridge owns transition facts but does not compute v2 scalar reward.
- Unknown enum values and incompatible major versions fail closed.
- Replays and checkpoints must record the contract, observation, reward,
  action-ordering, and game-data hashes used to create them.

`schemas/` contains JSON Schema 2020-12 documents. `openapi/` describes the
HTTP surface and scoped bearer requirements. `fixtures/` contains
transport-independent examples validated against the schema references declared
in `manifest.json`. `generated/` contains version constants generated by
`tools/contracts/generate_contract_versions.py`.

Run the mandatory dependency-free validator with:

```powershell
python tools/contracts/check_contracts.py
```
